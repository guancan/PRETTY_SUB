# 说话人分离迭代计划

## 目标

在豆包语音识别链路中支持可选的说话人分离，让多人音频可以按说话人展示、重命名，并在字幕导出时按需带上说话人名称。

## 关键判断

- 第一版采用显式开关：上传/识别前由用户选择是否开启“识别说话人”。
- 不做默认自动识别：不开启 API 参数时无法可靠判断是否多人讲话；默认开启也可能引入额外耗时、成本不确定性和误分说话人。
- 说话人只是聚类标签：先展示为“说话人 1 / 说话人 2”，不假设模型能识别真实姓名。
- 说话人信息不参与当前动态跳字字幕效果；它作为独立字段或文本前缀存在。

## 第一阶段：最小闭环

1. 增加识别开关
   - 在识别设置区增加“识别说话人”开关。
   - 默认关闭。
   - 开启时向豆包请求传入 `enable_speaker_info: true`。

2. 探测并解析返回结构
   - 用多人音频样本实测极速版返回字段。
   - 确认 speaker 信息挂载在 utterance、word，还是 additions。
   - 先兼容最小必要字段：`speakerId`、`speakerName`。

3. 更新内部数据模型
   - `TranscriptionUtterance` 增加 `speakerId`。
   - `SubtitleSegment` 增加 `speakerId`。
   - 如返回粒度只到 word，再按 segment 内主要 speaker 聚合。

4. 编辑器展示
   - 在字幕行时间点附近展示说话人标签。
   - 单人或无 speaker 信息时不展示标签。
   - 当前剪切、删除、文本编辑能力保持不变。

## 第二阶段：说话人管理

1. 聚合 speaker 列表
   - 从字幕片段中统计全部 speaker。
   - 默认命名为“说话人 1 / 说话人 2”。

2. 支持重命名
   - 用户可以把 speaker 改成“主持人”“嘉宾”“张三”等。
   - 重命名只改展示名，不改底层 `speakerId`。

3. 支持试听样例
   - 点击 speaker 后跳转到该 speaker 的一段代表性片段。
   - 第一版先做 seek 到片段起点，不做复杂片段队列播放。

## 第三阶段：字幕展示与导出

1. 增加显示设置
   - “在台词前添加说话人名字”开关。
   - 关闭时只在编辑器辅助展示 speaker。

2. 预览规则
   - speaker 可显示在正文字幕上方，或作为前缀展示。
   - 正文动态跳字仍只作用于台词文本。

3. 导出规则
   - SRT 导出支持 `说话人：台词` 前缀。
   - 视频烧录导出后续再接入 speaker 样式，避免第一版扩大范围。

## 验证路径

1. 单人音频
   - 开启说话人识别后不应误展示多个 speaker。

2. 双人对话音频
   - 识别后能出现至少两个 speaker 标签。
   - 每个 speaker 能定位到对应片段。

3. 编辑回归
   - 词级/字级剪切、删除、文本编辑仍正常。
   - 重新分段后 speaker 信息不应无故丢失。

4. 导出回归
   - 普通 SRT 导出不受影响。
   - 开启 speaker 前缀后，SRT 文案包含 speaker 名称。

## 暂不处理

- 自动判断是否多人讲话。
- 声纹注册或真实身份识别。
- 复杂 speaker 合并/拆分。
- speaker 独立样式编辑。
- 多 speaker 同一句重叠说话的精细处理。
