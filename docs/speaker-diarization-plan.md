# 说话人分离迭代计划

## 目标

在豆包语音识别链路中支持可选的说话人分离，让多人音频可以按说话人展示、修正、命名，并在字幕导出时按需带上说话人名称。

## 当前状态

- 已支持识别前显式开启“识别说话人”。
- 已向豆包请求传入 `enable_speaker_info: true`。
- 已验证豆包极速版真实返回结构：说话人字段位于 `result.utterances[].additions.speaker`。
- 已将 speaker 信息从豆包分句写入转写分句、词和字幕片段。
- 已在编辑器时间点附近展示基础说话人标签。
- 已确认双人音频可得到 `说话人 1 / 说话人 2`；单人口播可能被模型误分为多个 speaker，需要手动归并能力兜底。

## 关键判断

- 第一版采用显式开关：上传/识别前由用户选择是否开启“识别说话人”。
- 不做默认自动识别：不开启 API 参数时无法可靠判断是否多人讲话；默认开启也可能引入额外耗时、成本不确定性和误分说话人。
- 豆包的说话人结果只作为默认值：模型负责初始聚类，用户负责最终确认和修正。
- 说话人只是聚类标签：默认展示为“说话人 1 / 说话人 2”，不假设模型能识别真实姓名。
- 说话人信息不参与当前动态跳字字幕效果；它作为独立字段或文本前缀存在。

## 数据模型

建议引入独立 speaker 表，字幕段只引用 `speakerId`：

```ts
type Speaker = {
  id: string;
  name: string;
  source: 'provider' | 'manual';
};

type SubtitleSegment = {
  speakerId?: string;
  speakerName?: string; // 过渡字段，后续可由 Speaker.name 替代
};
```

规则：

- `Speaker.id` 使用豆包返回的 speaker id；手动新增时使用本地生成 id。
- `SubtitleSegment.speakerId` 是每句字幕的最终说话人引用。
- 重命名只更新 speaker 表，不批量改字幕段文本。
- 删除 speaker 必须先归并：把所有引用旧 `speakerId` 的字幕段改到目标 `speakerId`。

## 分句默认值

- 豆包返回的 `utterance.additions.speaker` 作为每个原始分句的默认说话人。
- 基于豆包分句生成字幕段时，直接继承该默认说话人。
- 如果后续规则分段或 AI 分段把多个来源合成一段，默认取靠前词/靠前分句的 speaker。

## 拆分与合并规则

用户通过换行符拆分句子，或通过删除操作合并句子时，按靠前句子的说话人处理：

- 拆分字幕：拆分后的多段默认继承原字幕段的 `speakerId`。
- 合并字幕：合并后的字幕段使用靠前字幕段的 `speakerId`。
- 删除换行导致合并：结果使用靠前字幕段的 `speakerId`。
- 如果用户认为默认值不对，可以对合并或拆分后的单句字幕手动改说话人。

## 第一阶段：基础能力固化

1. 清理调试日志
   - 保留低噪声开发日志：`logId`、分句数、speaker id 列表。
   - 不在服务端日志里打印完整转写正文。

2. 单 speaker 展示策略
   - 全局只有一个 speaker 时，默认不展示“说话人 1”标签。
   - 多 speaker 时展示标签。

3. 视觉区分
   - 不同 speaker 使用不同颜色标签。
   - 颜色只用于编辑辅助，不影响字幕动态效果。

## 第二阶段：说话人管理

1. 汇总展示
   - 展示当前所有说话人。
   - 展示每个说话人关联的字幕句数。

2. 重命名
   - 支持把“说话人 1”改成“主持人”“嘉宾”“张三”等。
   - 重命名后所有引用该 speaker 的字幕段同步显示新名字。

3. 新增说话人
   - 支持用户手动新增 speaker。
   - 新增 speaker 可被单句字幕选择引用。

4. 单句编辑
   - 支持对每一句字幕单独编辑说话人。
   - 选择范围：已有 speaker，也可以新建 speaker。

5. 删除与归并
   - 删除 speaker 前必须选择归并目标。
   - 归并后，旧 speaker 下所有字幕段转移到目标 speaker。
   - 多 speaker 模式下只剩一个 speaker 时，该 speaker 只能重命名，不能删除。

## 第三阶段：试听与校对

1. 试听样例
   - 点击 speaker 后定位到该 speaker 的代表性字幕片段。
   - 第一版先做 seek 到片段起点，不做复杂片段队列播放。

2. 快速校对
   - 支持筛选某个 speaker 的字幕句。
   - 支持从筛选结果逐句跳转校对。

## 第四阶段：字幕展示与导出

1. 增加显示设置
   - “在台词前添加说话人名字”开关。
   - 关闭时只在编辑器辅助展示 speaker。

2. 预览规则
   - speaker 可显示在正文字幕上方，或作为台词前缀展示。
   - 正文动态跳字仍只作用于台词文本。

3. 导出规则
   - SRT 导出支持 `说话人：台词` 前缀。
   - 视频烧录导出后续再接入 speaker 样式，避免第一版扩大范围。

## 验证路径

1. 单人音频
   - 开启说话人识别后，如果只识别到一个 speaker，应默认隐藏 speaker 标签。
   - 如果模型误分多个 speaker，应能通过“删除并归并”修正。

2. 双人对话音频
   - 识别后能出现至少两个 speaker 标签。
   - 不同 speaker 标签可视觉区分。
   - 每个 speaker 能定位到对应片段。

3. 手动编辑
   - 能重命名 speaker。
   - 能新增 speaker。
   - 能对单句字幕改 speaker。
   - 删除 speaker 时必须完成归并。

4. 拆分合并
   - 拆分字幕后，新字幕继承原 speaker。
   - 合并字幕后，结果使用靠前字幕的 speaker。
   - 删除换行导致合并后，结果使用靠前字幕的 speaker。

5. 编辑回归
   - 词级/字级剪切、删除、文本编辑仍正常。
   - 重新分段后 speaker 信息不应无故丢失。

6. 导出回归
   - 普通 SRT 导出不受影响。
   - 开启 speaker 前缀后，SRT 文案包含 speaker 名称。

## 暂不处理

- 自动判断是否多人讲话。
- 声纹注册或真实身份识别。
- 多 speaker 同一句重叠说话的精细处理。
- speaker 独立字幕动画。
