# 说话人分离迭代计划

## 目标

在豆包语音识别链路中支持可选的说话人分离，让多人音频可以按说话人展示、修正、命名，并在字幕导出时按需带上说话人名称。

## 当前状态

- 已支持识别前显式开启“识别说话人”。
- 已向豆包请求传入 `enable_speaker_info: true`。
- 已验证豆包极速版真实返回结构：说话人字段位于 `result.utterances[].additions.speaker`。
- 已将 speaker 信息从豆包分句写入转写分句、词和字幕片段。
- 已在编辑器时间点附近展示基础说话人标签。
- 已确认双人音频可得到 `说话人 1 / 说话人 2`；单人口播可能被模型误分为多个 speaker，需要手动归并能力兜底。
- 已增加轻量 speaker 汇总入口：展示说话人列表、句数、颜色，并支持定位到该 speaker 的第一句。
- 已支持在轻量入口中重命名 speaker，并同步到所有引用该 `speakerId` 的字幕段。
- 已支持新增 speaker，并可在单句左侧选择已有 speaker。
- 已支持删除空 speaker；有字幕引用的 speaker 需先归并到其他 speaker。
- 已初步压缩字幕编辑器排版，并将单句左侧结构收拢为“手柄/菜单入口 + 说话人 + 时间戳”。
- 已增加轻量句子菜单：支持整句剪切、整句删除和展开位置调整。
- 已将整句菜单视觉对齐字/词菜单，并补充整句颜色、整句恢复，以及剪切时同时包含当前句子内可见 gap。
- 已将默认竖屏编辑布局调整为编辑器优先：默认约 75% 宽度，支持拖动分栏，预览区保留最小可见宽度；横屏视频继续保留原左右布局。

## 关键判断

- 第一版采用显式开关：上传/识别前由用户选择是否开启“识别说话人”。
- 不做默认自动识别：不开启 API 参数时无法可靠判断是否多人讲话；默认开启也可能引入额外耗时、成本不确定性和误分说话人。
- “区分说话人”和“不区分说话人”是两个明确模式：只有用户开启区分说话人后，才展示和管理 speaker 信息。
- 区分说话人模式下，即使当前只识别出一个 speaker，也应保留 speaker 展示与编辑入口，方便后续填写、重命名和校正。
- 豆包的说话人结果只作为默认值：模型负责初始聚类，用户负责最终确认和修正。
- 说话人只是聚类标签：默认展示为“说话人 1 / 说话人 2”，不假设模型能识别真实姓名。
- 说话人信息不参与当前动态跳字字幕效果；它作为独立字段或文本前缀存在。

## 数据模型

建议引入独立 speaker 表，字幕段只引用 `speakerId`：

```ts
type Speaker = {
  id: string;
  name: string;
  source: 'provider' | 'manual';
};

type SubtitleSegment = {
  speakerId?: string;
  speakerName?: string; // 过渡字段，后续可由 Speaker.name 替代
};
```

规则：

- `Speaker.id` 使用豆包返回的 speaker id；手动新增时使用本地生成 id。
- `SubtitleSegment.speakerId` 是每句字幕的最终说话人引用。
- 重命名只更新 speaker 表，不批量改字幕段文本。
- 删除 speaker 必须先归并：把所有引用旧 `speakerId` 的字幕段改到目标 `speakerId`。

## 分句默认值

- 豆包返回的 `utterance.additions.speaker` 作为每个原始分句的默认说话人。
- 基于豆包分句生成字幕段时，直接继承该默认说话人。
- 如果后续规则分段或 AI 分段把多个来源合成一段，默认取靠前词/靠前分句的 speaker。

## 拆分与合并规则

用户通过换行符拆分句子，或通过删除操作合并句子时，按靠前句子的说话人处理：

- 拆分字幕：拆分后的多段默认继承原字幕段的 `speakerId`。
- 合并字幕：合并后的字幕段使用靠前字幕段的 `speakerId`。
- 删除换行导致合并：结果使用靠前字幕段的 `speakerId`。
- 如果用户认为默认值不对，可以对合并或拆分后的单句字幕手动改说话人。

## 第一阶段：基础能力固化

1. 清理调试日志
   - 保留低噪声开发日志：`logId`、分句数、speaker id 列表。
   - 不在服务端日志里打印完整转写正文。

2. 模式展示策略
   - 不区分说话人模式下，不展示 speaker 标签和管理入口。
   - 区分说话人模式下，只要字幕段存在 `speakerId`，就展示 speaker 标签。
   - 区分说话人模式下，即使全局只有一个 speaker，也不隐藏标签。

3. 视觉区分
   - 不同 speaker 使用不同颜色标签。
   - 颜色只用于编辑辅助，不影响字幕动态效果。

4. 轻量管理入口
   - 从当前字幕段派生 speaker 汇总。
   - 展示 speaker 列表、句数和颜色。
   - 支持点击 speaker 定位到第一条关联字幕。

## 第二阶段：说话人管理

1. 汇总展示
   - 已完成轻量版：展示当前所有说话人。
   - 已完成轻量版：展示每个说话人关联的字幕句数。
   - 后续可升级为可编辑的管理面板。

2. 重命名
   - 已完成轻量版：支持把“说话人 1”改成“主持人”“嘉宾”“张三”等。
   - 已完成轻量版：重命名后所有引用该 speaker 的字幕段同步显示新名字。

3. 新增说话人
   - 已完成轻量版：支持用户手动新增 speaker。
   - 已完成轻量版：新增 speaker 可被单句字幕选择引用。

4. 单句编辑
   - 已完成轻量版：支持对每一句字幕单独编辑说话人。
   - 已完成轻量版：选择范围为当前已有 speaker。

5. 删除与归并
   - 已完成轻量版：删除有字幕引用的 speaker 前必须选择归并目标。
   - 已完成轻量版：归并后，旧 speaker 下所有字幕段转移到目标 speaker。
   - 已完成轻量版：没有字幕引用的手动 speaker 可直接删除。
   - 多 speaker 模式下只剩一个有字幕引用的 speaker 时，该 speaker 只能重命名，不能删除。

## 第三阶段：试听与校对

1. 试听样例
   - 点击 speaker 后定位到该 speaker 的代表性字幕片段。
   - 第一版先做 seek 到片段起点，不做复杂片段队列播放。

2. 快速校对
   - 支持筛选某个 speaker 的字幕句。
   - 支持从筛选结果逐句跳转校对。

## 第四阶段：字幕展示与导出

1. 增加显示设置
   - “在台词前添加说话人名字”开关。
   - 关闭时只在编辑器辅助展示 speaker。

2. 预览规则
   - speaker 可显示在正文字幕上方，或作为台词前缀展示。
   - 正文动态跳字仍只作用于台词文本。

3. 导出规则
   - SRT 导出支持 `说话人：台词` 前缀。
   - 视频烧录导出后续再接入 speaker 样式，避免第一版扩大范围。

## 验证路径

1. 单人音频
   - 开启说话人识别后，如果只识别到一个 speaker，也应保留 speaker 标签和后续编辑入口。
   - 如果模型误分多个 speaker，应能通过“删除并归并”修正。

2. 双人对话音频
   - 识别后能出现至少两个 speaker 标签。
   - 不同 speaker 标签可视觉区分。
   - 每个 speaker 能定位到对应片段。

3. 手动编辑
   - 能重命名 speaker。
   - 能新增 speaker。
   - 能对单句字幕改 speaker。
   - 删除 speaker 时必须完成归并。

4. 拆分合并
   - 拆分字幕后，新字幕继承原 speaker。
   - 合并字幕后，结果使用靠前字幕的 speaker。
   - 删除换行导致合并后，结果使用靠前字幕的 speaker。

5. 编辑回归
   - 词级/字级剪切、删除、文本编辑仍正常。
   - 重新分段后 speaker 信息不应无故丢失。
   - 单句左侧手柄入口可展开句子菜单；整句剪切、整句删除、位置调整、说话人选择、时间戳 hover 和词级选择互不干扰。
   - 整句剪切时，句子内可见 gap 应同时进入剪切态；整句恢复后文字和 gap 都回到未剪切/未删除状态。
   - 整句颜色只批量作用于字幕文字，不作用于 gap。

6. 竖屏编辑布局
   - 竖屏或音频预览默认编辑器占比约 75%。
   - 拖动中间分栏后，编辑器最小不低于 50%，预览区仍保持可见。
   - 横屏视频保持原左右布局，不引入竖屏分栏拖动逻辑。

7. 导出回归
   - 普通 SRT 导出不受影响。
   - 开启 speaker 前缀后，SRT 文案包含 speaker 名称。

## 暂不处理

- 自动判断是否多人讲话。
- 声纹注册或真实身份识别。
- 多 speaker 同一句重叠说话的精细处理。
- speaker 独立字幕动画。
